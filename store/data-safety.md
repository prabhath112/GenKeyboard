# Play Console → App content → Data safety

Answers that match `PRIVACY.md` and the code. Do not claim less than this.

## Overview questions

- **Does your app collect or share any of the required user data types?** Yes
- **Is all of the user data collected by your app encrypted in transit?** Yes (HTTPS only)
- **Do you provide a way for users to request that their data is deleted?** Yes. The server stores nothing about the user except a daily counter keyed by a random device id, which expires in 48 hours. Clearing app data resets the id. State this in the "how to request deletion" URL by pointing to PRIVACY.md.

## Data types

### Personal info → Other info
- **Collected**: Yes. The text in the input field when the user taps an AI action.
- **Shared**: Yes, with the AI provider (Google Gemini, OpenRouter) to produce the result. Sharing is "for app functionality"; it is processing by a service provider, not sale.
- **Processed ephemerally**: Yes (not stored beyond the request).
- **Required or optional**: Optional (user must tap an action).
- **Purpose**: App functionality.

### Device or other IDs
- **Collected**: Yes. A random UUID generated by the app, not the Android ID or advertising ID.
- **Shared**: No.
- **Processed ephemerally**: No (daily counter kept up to 48 hours).
- **Required or optional**: Required for AI features.
- **Purpose**: App functionality (fair-use limit), fraud prevention and abuse.

### Everything else
Not collected: location, contacts, photos, files, health, financial, messages (other than the field text above), app activity, crash logs to us, search history, installed apps.

## Not collected, say so explicitly if asked
- No analytics SDK, no advertising SDK, no crash reporting SDK.
- Keystrokes, clipboard, suggestions and personal dictionary never leave the device.

## Security practices (self-declared)
- Encryption in transit: Yes.
- Deletion request mechanism: Yes (see above).
- Independent security review: No.
